# 企业情报研究助手

面向企业战略、市场与行业研究人员的研究工具，围绕单家公司、时间范围和主题整理资料，经过人工审核后生成带来源的简报。

当前为 **V0.4 桌面端本地交互原型**。已支持创建任务、自动搜索与网页正文读取、手动录入、本地 PDF/TXT/Markdown 导入、URL 与文件重复提示、人工审核、规则摘录、引用查看和 Markdown 导出。独立事件提取和内容相似度去重尚未实现。

界面采用“来源与状态”方案：顶部四步导航、统一研究范围栏、并排的资料列表与原文。示例体验通过顶栏入口展开独立右侧栏，默认收起，主界面只保留正式研究流程。当前仅面向桌面浏览器，建议窗口宽度至少 1120px；已移除手机端专属布局、按钮和交互。资料编号在审核、简报及导出中保持对应。设计使用 [Impeccable](https://github.com/pbakaus/impeccable) 的流程和审查规则，代码由本项目实现。

## 本地运行

安装 Node.js 22.13 或以上版本，在项目目录执行：

```powershell
npm ci --omit=optional
npm start
```

打开终端显示的地址，默认是 http://127.0.0.1:4173 。首次运行需安装锁定的 PDF.js 依赖；文件解析组件由本地服务提供，不依赖 CDN。保持服务运行，按 Ctrl+C 停止。

点击顶栏“示例体验”，再在侧栏中点击“载入示例任务”，可载入 5 条自主编写的虚构资料，包括未知日期、范围外和无正文的情况。示例公司和事件均为虚构，不代表真实企业动态。也可以创建自己的任务并手动录入来源和原文片段。

当前任务、保存正文和审核选择保存在本机浏览器的 localStorage；没有任务历史、云端同步或服务端数据库。报告需要在刷新后重新生成。清空或替换任务前会提示确认，请及时导出简报。只有点击搜索或读取操作才会请求资料服务，手动录入链接本身不会触发访问。

## 自动搜索与网页读取

配置现有 `DEEPSEEK_API_KEY` 并重启服务后，在“收集资料”页点击“搜索并读取正文”。系统按公司、主题与日期生成可修改的检索词，通过第三方 DeepSeek Search 搜索最多 5 条候选，再逐条调用 DeepSeek Fetch 读取公开网页为文本。也可粘贴单个公开网页链接，点击“读取网页”。两类接口复用模型密钥，不需要新增前端凭据。接口能力与计费参考 [DeepSeek 搜索与抓取说明](https://api-docs.deepseek.com/zh-cn/guides/search/)。

检索词与所读取的链接会发送至 DeepSeek，搜索、读取及简报生成可能分别产生费用；没有自动付费重试。搜索摘要单独显示，不能充当保存正文。读取成功、失败和待读取状态逐条保留；失败可重试，停止会保留已经完成的资料，刷新后可继续读取。再次搜索会跳过已有的规范化 URL，不覆盖原正文或审核选择；尚无内容相似度去重。

自动资料默认待审核，无正文不能纳入。来源名称、日期来自搜索元数据或网站域名，日期可能与正文、时区或实际发布日期不一致；检索条件不保证覆盖或精确过滤。进入审核后展开“核实来源信息与备注”，对照原文修正来源与日期、记录口径差异，再选择纳入或排除。未知日期请留空，不使用收集时间代替。

每条结论的相关来源若被标记待核实，或存在未知日期、范围外日期、截取和未核实搜索日期等提示，程序会在页面及 Markdown 附加来源提示；完整备注保留在对应来源区，避免依赖模型是否复述标记。提示只能说明来源需核查，不能证明结论真伪。

正文最多保存 12,000 字，超限明确记录原提取字数与截取；服务响应限制 2 MiB、单次超时 30 秒。扫描件、需登录、动态加载、站点访问限制和部分 PDF 可能无法读取，可使用本地文件导入。应用只请求固定的 DeepSeek 服务接口，不向目标站点发送本地密钥、浏览器 Cookie 或登录信息；本机、内网后缀、IP 地址、非默认端口和带账户信息的链接会被拒绝。第三方 Fetch 的结果仍需核对，不宣称自研网页解析器或绕过访问限制。

## 从本地文件导入

在“收集资料”页点击“导入本地文件”，逐个选择 PDF、TXT 或 Markdown（.md），单个文件不超过 10 MB。文件在浏览器内提取文字，原文件不会上传或保存到服务器。

PDF 可选择起止页码，每次最多提取 100 页；先预览并编辑正文，再补充标题、来源名称、发布日期和可选原文链接。不要把文件修改日期当作资料发布日期。TXT/Markdown 支持 UTF-8、GB18030 以及带 BOM 的 UTF-16。扫描版 PDF 暂不支持 OCR，受密码保护的 PDF 需先解密。

单条保存文本上限仍为 12,000 字。超过时只预填前 12,000 字，并保留截取提示；可改选相关 PDF 页码后重新提取。保存后的资料默认为待审核，同一文件及相同 PDF 页码范围会提示重复候选。原文件名、SHA-256 指纹、页码范围和截取情况随资料保存，并进入报告及 Markdown 引用；浏览器仅保存元数据与选定文本，原 PDF 请自行保管。

本地导入不调用模型或正文服务。之后选择 DeepSeek 并点击生成时，纳入的保存文本才会发送至模型服务。PDF 文字顺序、表格和日期仍需对照原文核查；当前没有批量文件导入、OCR 或 Word/Excel 解析。

## 可选：配置 DeepSeek

将 `.env.example` 复制为 `.env`，在本机填写 `DEEPSEEK_API_KEY`，并按开放平台账户可用模型设置 `DEEPSEEK_MODEL`，重启服务。参考 [DeepSeek 官方接入说明](https://api-docs.deepseek.com/zh-cn/)。密钥仅由本地服务读取，`.env` 已被 Git 忽略，不要在聊天、代码或提交中粘贴密钥。

配置后可在简报页选择 DeepSeek。用户点击生成时，纳入的资料正文会发送到 DeepSeek API，可能产生服务费用。未配置时可使用“规则摘录”，不会调用模型。当前摘要请求使用非思考模式、6,000 tokens 输出上限，并要求最多 12 条简短结论；截断、空正文、JSON 或引用校验失败分别提示，不自动重试。

已通过浏览器界面完成首个小米真实案例：导入三份季度公告第 6 页、核对末页发布日期、审核纳入、真实调用、引用查看和 Markdown 导出。首次生成失败后定位到输出长度上限，修复后两次成功；最终 12 条结论均在关联保存文本中找到依据，但 YU7 的 5 月/6 月表述差异未被模型主动汇总，结论级待核实标签仍有遗漏。此结果不代表真实事实审计、普遍准确率或完整 P0 验收；费用基线尚未建立。详见 [V0.3.1 真实案例验证](docs/verification-v0.3.1.md)。

V0.4 新增一次自动收集案例：真实搜索 5 条、读取成功 5 条，人工式审核纳入 2 条转载资料并更正日期、记录同源限制，真实生成并导出。最终 5 条结论均附有程序生成的来源待核实提示；模拟响应另行验证模型漏写标签时仍会显示提示。结果仍有主题偏移和概括粒度问题，不代表独立交叉验证、完整前三季度覆盖或一般准确率，详见 [V0.4 验证记录](docs/verification-v0.4.md)。

引用 ID 检查只能识别缺失、未知或不属于纳入资料的引用；无法自动证明结论被正文支持，仍需要人工核查。规则摘录按来源列出最多 500 字原文片段，时间线按资料发布日期整理。

## 验证

```powershell
npm test
```

浏览器回归需要 Playwright，可使用已有安装，或执行 `npm install --no-save --package-lock=false playwright` 后运行 `npm run test:browser`。脚本优先使用 Windows 默认路径下的 Chrome；其他路径可通过 `CHROME_PATH` 设置，也可使用 Playwright 自带浏览器（需另行安装）。

浏览器回归脚本会启动独立测试服务，使用虚构数据和模拟模型响应，结束后停止测试服务；截图及导出结果写入被 Git 忽略的 `outputs/`。V0.4 使用浏览器专用控制实际操作真实服务，边界情况使用 `node tests/research-fixture-server.mjs` 提供的独立虚构服务（端口 4176，不会调用真实 API）；本轮未重跑原有全套浏览器脚本。文件导入历史回归见 [V0.3 记录](docs/verification-v0.3.md)，自动收集与最新验证范围见 [V0.4 记录](docs/verification-v0.4.md)。
