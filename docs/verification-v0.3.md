# V0.3 本地文件导入验证

- 日期：2026-10-29
- 范围：收集资料页的 PDF、TXT、Markdown 导入，预览与选页，文件来源审核和导出。
- 环境：Windows、Node.js 22.23.2、Chrome、Playwright；桌面宽度 1120、1280、1440px。
- 依赖：Mozilla PDF.js 的 pdfjs-dist 6.4.299（Apache-2.0），锁定版本与依赖完整性；组件由本地服务托管。

## 自动检查

`node --test tests/core.test.mjs tests/import.test.mjs tests/server.test.mjs`：18 项通过。

新增检查覆盖：文件格式、空文件与 10 MB 限制；UTF-8、GB18030、带 BOM 的 UTF-16 文本；二进制伪装文本；12,000 字截取记录；页码范围和 100 页限制；文件指纹；来源结构校验、文件/选页重复候选；文件来源的报告快照和 Markdown 信息；PDF 组件资源白名单与路径访问隔离。既有任务、日期、资料审核、引用和模型模拟检查通过。

## 浏览器回归

`node tests/browser.cjs`：通过，包含 `tests/import-checks.cjs` 的端到端导入流程。

- 从收集页选择文件，自动带入文件名、读取文本，预览可编辑，发布时间初始留空；本地资料不强制外部链接，填写时仍拒绝危险协议。
- TXT 与 Markdown 同内容改名提示重复；导入文本中的脚本作为普通文字显示，不执行。
- 保存后资料待审核，浏览器刷新仍能恢复文件元数据；纳入后引用及 Markdown 保留文件名、指纹、页码和实际保存文本。
- 自主生成的两页 PDF 可提取全文，也能改为只保留第 2 页；页码修改后必须重新提取，非法范围不能保存。
- 超过 100 页的 PDF 不自动读取全文，选择较小范围后可提取。
- 不支持的类型、空文件、超大文件、二进制文本、伪装 PDF 和损坏 PDF 均提示失败，未添加资料；无文字 PDF 不自动生成可用正文。
- 超限文本保留明确截取提示并标记待核实；取消 PDF 读取后能正常手动录入，不会被迟到结果覆盖。
- 验证期间阻止并记录外部网络请求，文件导入流程没有远程请求；模型生成仍使用规则摘录或模拟响应，未调用付费 API。
- 审核页及导入窗口无横向内容溢出，运行无页面脚本异常。手机端不在支持范围。

## 尚未覆盖与约束

当前逐个导入文件，不支持批量队列、Office 文档、扫描件 OCR 或直接读取加密 PDF。PDF 按提取顺序形成文本，复杂表格和多栏阅读顺序仍须人工核对；选页和截取不代表完整文件覆盖。只保存元数据与选定文字，原文件由用户保管。自动搜索、网页读取及真实研究简报质量评估继续待完成。
