# V0.6 调用记录验证

- 日期：2026-10-31（北京时间）。
- 目标：为真实研究验收建立外部调用的状态、耗时与用量记录；本轮只交付软件实现与合成验证。
- 实现：Codex 在用户指导下完成；独立代理按 Impeccable 技能复核界面和设计系统一致性，不属于产品内子智能体能力。

## 实现边界

搜索、网页读取与模型生成每次进入外部调用前建立独立记录，响应头提供 `X-Call-Id`。任务/资料 ID 仅用于关联；不保存公司、主题、查询、网址、保存正文、模型输出或密钥，不创建完整任务历史。手动重试作为不同调用保留，可按相同任务和资料 ID 核对；没有逻辑重试链或自动重试。

记录成功、失败、已取消、进行中，以及上次服务运行遗留的未完成请求。耗时用单调计时器测量，包含初始记录准备、服务响应与应用结果校验，结束写入耗时未计入；不是单独的模型推理速度。中断或重启不能证明供应商未执行/计费，重启记录不推算耗时和用量。模型输出上限、空正文、JSON/引用校验错误和网络/超时均记录固定编号，应用校验失败仍保留已收到的用量。

用量只接收供应商返回的 `prompt_tokens`、`completion_tokens`、`total_tokens`、`prompt_cache_hit_tokens` 与 `prompt_cache_miss_tokens` 非负整数，保留 0；缺失/非法字段为 null，页面显示未知，不凭其他字段补算。字段名核对自 [DeepSeek Chat Completions 官方文档](https://api-docs.deepseek.com/api/create-chat-completion/)。搜索/读取未返回用量时仍为未知；本轮不声称它们一定提供 token。费用始终为 null/未知，没有账单集成、计价或费用汇总。

本地 `data/calls.json` 与当前任务/资料库分开，可由 `CALL_LOG_PATH` 指定。仅支持一个本地服务进程写入，进程内串行、临时文件原子替换；最多 500 条，容量到达后移除旧已结束记录并保留进行中记录。读取或初始保存失败时不发起外部请求，损坏文件不覆盖；最终状态写入失败不把已完成结果改成模型失败，响应附加提示。此时磁盘中的运行状态可能未更新，需检查文件；不可推断实际用量。历史请求不会自动补录。

## 自动验证

`npm test`：**81 项通过，0 失败**。新增 13 项覆盖：

- 服务方用量的 0、未知、非法值与白名单字段；不把总量或费用从其他字段推算。
- 正常记录的持久化、任务/资料关联、供应商请求 ID/模型、耗时与单次终态；重复完成不会重复记账。
- 同一资料的独立调用、并发写入完整性、保留上限及进行中记录不被移除。
- 新服务实例将遗留进行中记录标为未完成，耗时/用量不编造。
- 损坏文件原样保留、记录失败、各元数据字段不携带原文或密钥。
- 调用记录 API 的来源/方法/任务编号校验与文件路径隔离。
- 本地搜索、读取、生成适配器的独立记录、响应头关联和精确模拟用量；输出校验失败、超时与未知用量。
- 浏览器断开后上游信号中断、取消记录完成、下一次生成释放锁；初始记录失败不发起供应商调用；最终状态保存失败仍返回成功结果并附提示。

所有新增测试使用临时文件或目录，未写正式 data/，未访问真实 DeepSeek。
