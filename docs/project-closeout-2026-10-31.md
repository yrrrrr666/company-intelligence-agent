# 项目阶段收尾记录（2026-10-31）

## 当前交付

企业情报研究助手是面向桌面浏览器的本地原型，围绕单家公司、时间范围和研究主题，支持手动及外部资料收集、PDF/TXT/Markdown 导入、人工纳入/排除、本地资料库与关键词检索、规则摘录或 DeepSeek 简报、引用查看、Markdown 导出及本地调用记录。本阶段增加了简报内的**人工**研究覆盖标注：用户可把检查项关联一条纳入资料和一条引用该资料的结论，并导出缺口。检查项不持久化，刷新或重新生成后需重做。

技术栈：JavaScript、HTML/CSS、Node.js、DeepSeek API 适配、PDF.js、localStorage、Playwright。参考项目与第三方工具不等于本项目集成的技术栈；当前没有 LangChain、LangGraph 或产品内多智能体调度。

## 验证证据

- 软件回归：`npm test` 82 项通过；主流程、资料库、检索和调用记录四组浏览器回归通过，覆盖 1120/1280/1440px 桌面布局。测试上游为合成响应，没有新增付费调用。
- 真实案例：此前用三份小米公告选页完成资料入库、检索、复审、一次 DeepSeek 生成、引用与导出。13 段库内片段经逐一文本比对；12 条生成结论在关联文本中找到支持，但遗漏已有资料中的一季度销售网络指标。详见 [真实案例记录](verification-v0.6-real-case.md)。
- 该次调用 4,687 token、请求处理耗时 5,299 毫秒；费用按供应商用量页人工核对为“不足 ¥0.01（供应商显示值）”。这是单次样本，不作为一般成本估计。

## 对外表述边界

可描述为“设计并开发本地企业情报研究原型，建立审核、检索复用、引用追溯和调用记录流程，并通过真实案例发现报告覆盖缺口”。实际个人职责须按本人贡献调整。

当前未进行目标用户访谈、目标用户任务测试或人工流程对照，不能宣称效率提升、通用准确率或商业成效。引用关联只证明引用 ID 指向纳入资料，不自动证明事实正确。覆盖检查依赖人工创建和判断，尚无自动遗漏识别、问题拆解、有限子任务调度或自动补证。历史真实案例没有在最新覆盖检查界面重新验收。

## 交接与恢复

仓库源码与文档可按 README 的 `npm ci --omit=optional`、`npm start` 在 Node.js 22.13+ 本机运行；正式数据位于 Git 忽略的 `data/` 和浏览器 localStorage，原始文件需另外备份。`outputs/` 下的真实案例材料、截图和账号财务核对文件同样不进入仓库。若继续开发，先依据真实案例补充覆盖检查验收，再决定是否投入自动规划或补证；这两项仍只是路线图。
