# V0.5.1 匹配上下文与检索评估验证

- 日期：2026-10-30（北京时间）。
- 目标：建立可复现的固定原文评估，改善长背景之后的关键依据展示，并保留无效改动与失败案例。
- 实现与审核：子智能体分别实现匹配/排序候选、界面和固定样本；后续使用另一模型继续评估审计与浏览器回归，主智能体审核集成、证据范围、方案选择和交付。用户中途要求保存，WIP 为 c1ce81f；同日恢复后完成下列工作。
- 真实材料与合成测试分开：固定检索评估使用官方公开正文，浏览器使用明确标注的合成资料和隔离临时库；没有调用真实 DeepSeek 或其他付费模型，没有写入用户正式资料库或重置浏览器当前任务。

## 实际变更

新增共享 `web/retrieval.mjs`，提供词匹配和最多 480 个 UTF-16 字符的连续原文上下文。保留原 900 字符容器片段、100 字符左右重叠与 ID；返回上下文及高亮位置均定位到保存原文，不能以生成文字代替。

列表与详情展示匹配附近上下文、安全高亮、实际位置和省略提示，可继续展开原容器和入库原文。导入前服务复核当前版本，客户端验证精确切片和高亮边界；加入后仍待审核，文档/版本/片段、实际字符位置、检索词、时间及历史问题保留。不同查询在同一容器中选出未被已有资料覆盖的上下文，仍可以继续加入。旧任务长片段规则摘录可按查询选取文字，而来源快照不改写。

修复长合并命中导致窗口计算崩溃、高亮超过协议上限、重复匹配造成预览计算开销，以及缩小上下文后误把同容器另一段依据视为重复的问题。关键词高亮始终先转义文本；异常标记位置以纯文字回退，导入异常上下文则拒绝。

实验排序候选被固定评估拒绝，最终恢复 V0.5 的词分数与优先展示不同文档的顺序，保留词边界资格检查、匹配上下文和冗余保护。候选归档与代码指纹仍在本地，不把实验排序写成已证明更好的实现。

## 固定评估与证据审核

评估清单位于 `evals/retrieval-v0.5.1/`，两家公司、六份官方正文、14 题（11 正例与 3 无答案控制）。其中 9 个正例与原文同语言，2 个跨语言问题仍共享年份等词元。全文均少于 12,000 字符；只提交 URL、日期、指纹、范围和短锚点，原文与完整返回文本在被忽略的 `outputs/v0.5.1-eval/`。

主智能体抽查三道题：NIO 二季度收入、小鹏一季度总收入、小鹏月度交付与 G6 大定，核对对应原文范围、期间、指标及单位；独立评估审计另外复核标题/发布日期和六份正文的重提取一致性。NIO 最初误拟为 Q1 的链接，依据官方正文在评估前更正为五月交付，未按算法结果修改标签。小鹏六月交付正文事件日与官网显示发布日期也单独区分。

runner 从 Git 821a40f 加载真实基线模块，当前方案调用实际 LibraryStore；固定相同的资料、审核状态、顺序、过滤和时间，对比前五结果。默认离线且校验原文/标签指纹，缺失或变化停止；显式 `--fetch` 才获取清单官方 URL。临时库隔离，不读取正式研究数据。schema 2 同时记录等长前 480 字符控制，便于区分预算增长与定位变化。

最终正例首条、前五及容器完整覆盖均为 11/11，与基线一致；实际预览完整覆盖从 1/11 到 9/11，同为前 480 字符的基线控制为 8/11。规则完整覆盖仍为 9/11，无答案返回仍为 2/3。实验候选首位命中退化、重叠增加而未提升前五覆盖，所以没有采用。题集参与版本选择，不能当作独立留出验证。完整分母、逐题失败、原候选和单次本地耗时见 [固定评估报告](retrieval-evaluation-v0.5.1.md)。

## 界面复核与边界

沿用既有桌面四步流程、资料双栏与独立默认收起示例侧栏。新高亮使用现有状态色，无新增栅格资源或视觉体系。检测器运行一次，75 项结果中 5 个 warning、70 个 advisory；主要为继有容器、对话框阴影及设计文档的颜色/字号建议，新局部高亮也有圆角建议，不宣称零警告。独立 finish reviewer 查看四张最终截图，未发现本次扩展的实质视觉问题；要求修正 PRODUCT 中“尚无检索评估基线”的过时事实，修正后 verdict pass 判定该项 resolved、disposition ship。该结论限于此修复，未重新认证继有 seed 或新 QUALITY BAR。

短上下文仍会遗漏多处必需证据：本组订单/交付比较由完整容器覆盖变为预览及规则不完整，另有跨语言收入题预览不完整。不能将高亮视为答案、检索命中视为事实核实，也不能把本组 11/11 容器命中写成准确率 100%。没有语义检索、可靠无答案判断、模型答案审计、独立留出测试、真实用户或效率/费用结论。当前检索处理的单次累计耗时高于基线，尚非受控性能评估。

文档复核依据当前代码和最终截图，沿用并保留 DESIGN.md 与设计 sidecar，只补充本次 surface 记录，不顺带修理既有体系差异。本机服务已在 4173 启动，首页及新 retrieval.mjs 均返回 200；健康检查没有搜索或模型请求。

交付前差异与凭据模式检查无命中；本轮变更未包含 data/、outputs/、node_modules/ 或私密环境文件。最终评估输出中的三份产品代码指纹均与当前工作区一致，未把旧候选的结果冒充最终实现。原文、完整结果和截图继续仅保存在被忽略的本地输出目录。
