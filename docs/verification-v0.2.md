## 需求与实现核对

用户确认保留四步流程、整体平衡，并选择顶部四步导航、统一展示研究范围、资料与原文并排的方案。实际实现移除了上一版的大口号、英文装饰标签、重复流程条及深色侧栏，使用深蓝顶部产品栏、浅色研究范围带、正常字号和统一状态色。主体正文为 14px，辅助信息最低为 12px。

原有存储键、任务与审核数据结构保留。规则摘录、可选 DeepSeek 模式、排除逻辑、引用查看与导出沿用原流程。新增的报告来源编号是报告快照字段，不需要迁移浏览器中的当前任务。

## 自动与浏览器验证

- 11 项 Node 自动检查全部通过：在前版 10 项基础上增加排除前置来源后的编号与 Markdown 锚点对应检查。
- 完整浏览器回归通过：任务校验、手动录入、URL 提示、HTML/脚本文本转义、纳入/排除、待核实、筛选、无正文限制、报告失效、刷新恢复、虚构示例替换确认、引用及 Markdown 下载。
- 使用模拟响应复测未配置模型、模型失败、重试成功及审核选择保留；未调用真实 API。
- 检查桌面 1440px，以及 1280、1024、768、659、390px 宽度，未发现横向溢出；659px 对应本轮内嵌浏览器的宽度。
- 检查键盘 Tab 焦点可见、表单与正文不低于 14px、手机端选中资料后正文进入视口，以及返回资料列表。
- 两轮批量视觉检查，查看创建、收集、审核、简报与移动端页面；第二轮压缩演示提示和资料行的冗余空间，避免列表过高造成右侧大面积空白。
- 无页面脚本异常。截图位于本机 `outputs/` 及 `.impeccable/review/`，不提交仓库。

## 设计检测与独立审查

仅运行一次 Impeccable detector；结果保存在本机 `outputs/ui-detection.json`。检测器报告 6 个警告：5 个容器内边距提示和 1 个深色发光提示。需结合子元素内边距、实际去除边框的演示提示，以及有垂直位移的弹窗阴影判断，不能据此直接宣称检测零问题。

独立 Impeccable finish reviewer 的结论为 **ship**，未提出需要修复的实质性问题。审查核对了产品记录、用户选择、原始 seed 输出、代码实现、所选 HTML 草图，以及八份有效页面截图；认为排版、材质、背景、首屏结构、资料对应关系、窄屏适配和事实边界符合本轮方向。

六个检测警告经独立核对后均未发现对应的渲染问题：步骤、筛选按钮与资料行有实际内边距；演示提示无边框；说明区在有侧边框时有相应内边距；弹窗和提示阴影有垂直位移，位于浅色页面。未添加屏蔽规则，也未重复运行检测器。

审查范围为视觉与交互设计；`web/app.mjs` 为抽读，运行行为依据上述测试结果，不将这一结论扩大为逐行代码或真实业务准确性审计。

审查后由独立 documenter 根据实际代码生成 `DESIGN.md` 与 `.impeccable/design.json`：记录实际颜色、字号、布局、控件状态及 10 个组件示例，完成 YAML、引用与 JSON 结构检查；未更改已审查的页面代码。产品记录和界面方向作为开发文档保存，不通过本地服务公开。
