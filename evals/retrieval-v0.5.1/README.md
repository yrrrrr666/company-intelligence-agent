# 固定资料检索评估

本目录仅保存公开来源清单、文本指纹与人工范围标注；完整原文与运行结果在被 Git 忽略的 `outputs/v0.5.1-eval/`。首次运行需显式下载官方网页：

```powershell
node scripts/evaluate-retrieval.mjs --fetch
node scripts/evaluate-retrieval.mjs
```

默认离线，文件缺失、网页正文指纹变化或标注越界会报错，不会替换为虚构数据。`--fetch` 只访问 manifest 中固定的官方 HTTPS URL；不需要模型密钥，不调用付费服务。网页可能变更或拒绝访问，此时应人工复核并另立评估版本，不能直接覆盖固定标签。

标签先依据实际原文确定，再运行改进算法。评价范围是两家公司、六份公司自行发布的资料、14 个固定问题；同源披露不是独立事实审计。英文和中文原文分别使用同语言问题，并单列跨语言检索失败。无答案控制与正例分开计数，不能把返回任何含相似词的片段算正确。

完整证据由一个或多个标注范围构成：必须同时包含期间、指标/单位和数值等上下文。范围位置按保存文本的 UTF-16 下标（左闭右开），与产品一致。原文太长时必须在 manifest 记录所用固定选段及映射，不能默认为全文。本版六篇正文均小于 12,000 字符，未做截取。

基线从本地 Git 的 `821a40f` 读取资料库和 core 源码，仅改写导入路径以便隔离加载；当前算法直接调用产品 LibraryStore。二者使用相同原文、公司、日期、审核状态、固定时间和前 5 个结果，临时库结束后清理。检索时间只是在本机实测，不是人工效率或供应商模型延时。

Hit@1/5 表示至少一个完整标注范围被一个返回片段覆盖；完整问题覆盖率要求该题全部必需范围被前 5 结果覆盖。另报告预览上下文完整覆盖率、规则摘录可见覆盖率、标注相关片段比例、重叠比例和逐题失败。相关比例仅针对人工标出的充分证据，未标出的其他潜在证据可能被计为不相关，不能解释为普遍准确率。

Delivered 23,231 Vehicles in May 2025`，`publish_time_str` 为 `2025-06-01`（CMS 创建时间为 6 月 3 日）。因此改为五月交付资料及月度/累计口径问题。该更正基于网页内容，在比较运行前完成；未因算法返回结果修改金标准。NIO 第二季度网页是公司新闻摘要，不是完整 IR 财报。全部六份保存 HTML 经固定提取器重提取，与 TXT 完全一致；所有证据范围的哈希和锚点均通过校验。
